# 3D Human Anatomy Explorer + MedGemma 1.5

Interactive human-body taxonomy available on the **Doctor**, **Patient** and **Caregiver** pages,
with explanations generated by Google's medical model **MedGemma 1.5** and grounded in the active
patient's EvoCare record.

```
┌──────────────────────────────┬──────────────────────────────────────┐
│  Sketchfab 3D body           │  Taxonomy: skeletal · muscular ·     │
│  (real-time layer isolation: │  nervous · cardiovascular · digestive│
│   bone / muscle / nervous…)  │  · integumentary · respiratory ·     │
│                              │  urinary                             │
│  [All layers] [Isolate]      │  Ask MedGemma → grounded answer      │
│                              │  + linked evidence codes             │
└──────────────────────────────┴──────────────────────────────────────┘
```

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/api/anatomy/systems` | Taxonomy used by the viewer |
| `GET` | `/api/anatomy/status` | Which model tier is live (MedGemma / Gemini / Groq / offline) |
| `POST` | `/api/patients/{code}/anatomy/explain` | `{system?, structure?, question?, audience?}` → grounded explanation |

Audience defaults to the caller's role (`DOCTOR`→clinical tone, `PATIENT`→second-person plain
language, `CAREGIVER`→observation tips). Every call is audited as `ANATOMY_EXPLAIN` and never writes
to the clinical record.

## What MedGemma 1.5 is (and isn't)

* `google/medgemma-1.5-4b-it` – a 4B-parameter Gemma-3 variant trained on medical text and
  imaging (CXR, CT/MRI, histopathology, lab reports, EHR text). Open weights, gated on Hugging Face
  (accept the licence once). Context 128K tokens, text output only.
* There is **no hosted Google API** for it – you run it yourself (or through the HF inference router).
  EvoCare therefore speaks to it over the standard **OpenAI-compatible `/chat/completions`** route.
* The model card is explicit that it is a *developer* model, not a validated clinical device.
  EvoCare treats it accordingly: every prompt is grounded in the patient record, told to answer
  "not recorded" otherwise, forbidden from diagnosing/prescribing, and the UI shows a disclaimer.

## Connecting MedGemma

Pick one and set the variables in `.env` (root or `EvoCare/backend/.env`):

**1. vLLM (GPU, best quality)**
```bash
pip install vllm && huggingface-cli login
vllm serve google/medgemma-1.5-4b-it --port 8001 --max-model-len 16384
# .env
MEDGEMMA_BASE_URL=http://localhost:8001/v1
```

**2. Ollama (CPU/laptop friendly, quantised GGUF)**
```bash
ollama pull hf.co/unsloth/medgemma-1.5-4b-it-GGUF:Q4_K_M
# .env
MEDGEMMA_BASE_URL=http://localhost:11434/v1
MEDGEMMA_MODEL=hf.co/unsloth/medgemma-1.5-4b-it-GGUF:Q4_K_M
```

**3. Hugging Face Inference Router (no local GPU)**
```bash
# .env
MEDGEMMA_BASE_URL=https://router.huggingface.co/v1
MEDGEMMA_API_KEY=hf_xxx          # token with access to the gated repo
MEDGEMMA_MODEL=google/medgemma-1.5-4b-it
```

Optional: `MEDGEMMA_PRIMARY_FOR_REASONING=true` also puts MedGemma in front of Gemini/Groq for the
doctor's *Clinical AI Assistant* JSON reasoning.

Fail-over order for anatomy explanations: **MedGemma → Gemini Flash → Groq → offline deterministic
engine** (which still produces a record-grounded answer with linked evidence, so the demo never
breaks).

## Making the answers good – practical tips

1. **Ground, don't trust recall.** The 4B model hallucinates when asked open questions; it performs
   well when the facts are in the prompt. `build_anatomy_prompt()` already injects diagnoses,
   medications, caregiver observations and memory claims – keep it that way.
2. **Greedy decoding.** The Jan-2026 model card switched the default to greedy; we send
   `temperature 0.2` for prose and `0.0` for JSON.
3. **Structure the output.** Fixed markdown headings (`What it is / How it connects / What to watch
   for`) dramatically improve consistency and make the UI predictable.
4. **Audience prompts.** Tone rules per role live in `_audience_instructions()`; tune wording there.
5. **Use the 27B variant for doctors if you have the GPU** – just change `MEDGEMMA_MODEL`.
6. **Images later.** MedGemma 1.5 is multimodal; when you add X-ray/CT uploads, extend
   `MedGemmaProvider.chat()` to send `{"type":"image_url"}` parts – the OpenAI schema supports it.

## Real-time bone / muscle / nervous separation

The component loads the Sketchfab Viewer API (`sketchfab-viewer-1.12.1.js`), reads the scene's
node map, and on **Isolate layer** hides every node whose name doesn't match the selected system
(`LAYER_MATCHERS`). If the viewer API can't load (offline / CSP), it silently degrades to the plain
embed you provided, so the page always renders. To swap in your own segmented model change
`SKETCHFAB_MODEL_UID` or point the iframe at your own viewer.
